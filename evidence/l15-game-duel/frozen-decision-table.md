# L15 冻结判据表 · 同题双臂真实任务对照

> **冻结声明**：本表在跑数前冻结（sha256 见 `frozen-decision-table.sha256`，服务端时间戳即「先于见数」，沿第 122 轮起的 preregistration 外部化流程）。见数后不得增删判据、不得改判词映射。结果侧只按本表落格。

## 一 · 双臂协议

| 项 | 冻结值 |
|---|---|
| 题目 | 《雾井地牢》，需求＝[frozen-requirements.md](frozen-requirements.md) 逐字 |
| 臂数 | 2：**甲臂（直推对照）**／**乙臂（CtxKey 处理）** |
| 轮数 | 每臂 **12 轮**：轮 1 发完整需求＋空脚手架；轮 2–6 初始开发；**轮 7 只发 R6 变更单**；轮 8–12 完成与打磨 |
| 每轮产出 | 当版完整 `game.py` 全文 ＋ ≤300 字变更说明 |
| 模型 | 两臂**同一模型、同参数（温度 0）、同 API 端点**；具体 id 跑数时记录进结果侧，事后不得换臂 |
| 甲臂上下文 | 每轮把完整历史（需求＋历轮全部代码与说明＋变更单）直推给模型 |
| 乙臂上下文 | 全部材料以条目入 CtxKey；每轮按当下任务 compact 至 **B＝6 条活动上下文**，recall 按当轮任务触发；模型只见被选出条目拼接的上下文。CtxKey 参数用仓库公开缺省，不调参 |
| 记账 | 乙臂全程 ledger 落盘；甲臂记录每轮输入 token 量（对照） |
| 预算公平 | 同轮数、同每轮输出上限；乙臂输入更短是处理本身，不算不公平，但计入限度 |

## 四 · 判词映射（预注册，见数后不得改）

| 条件 | 判词 |
|---|---|
| 乙臂任一客观项劣于甲臂 | **处理臂受损**（falsifier 方向命中），逐条记录是哪条 |

| 乙 O 全条 ≥ 甲 且 Σ(乙)−Σ(甲) ≥2 | **方向性信号** |
| 其余中间态 | **部分**（只报不判） |

任何判词都**不得**写成「上下文选择提高任务成功率」的证明。

## 五 · 限度（先声明）

1. n＝1 双臂、单题目、单模型、园主单人盲评——任何结果都不是统计证明。
2. 本实验的定位：第一份**真实任务**对照＋CtxKey 在真实开发任务里的可运行性证据。
3. 显形依赖「装不下/挡路」：若 12 轮的题料没把甲臂上下文挤到压力区，无分辨是预期结果而非装置失败（见母库押注 2 与第 165 注）。
4. 乙臂模型见到的料更少是处理本身；若因此受损，按判词映射如实落「处理臂受损」。
