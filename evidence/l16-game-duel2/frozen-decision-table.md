# L16 冻结判据表 · 工程态保护三臂对照（雾井地牢·第二轮）

> **冻结声明**：本表在跑数前冻结（sha256 见 `frozen-decision-table.sha256`，服务端时间戳即「先于见数」）。见数后不得增删判据、不得改判词映射。需求沿用 L15 的 [../l15-game-duel/frozen-requirements.md](../l15-game-duel/frozen-requirements.md) 逐字（含 R6 变更单与两处埋雷），不重复冻结。

## 一 · 来路（本实验要验什么）

L15 收口的逐轮取证（4/4 相关）：乙臂（CtxKey B=6）黄铜钥匙蒸发的三个轮次，活动区均无任何代码条目——需求文档承载的冻结约束全程守住，**代码条目承载的工程态在挤出时蒸发**。本轮验证最小修复假设：

> **H16：把「最新一版代码」条目 pinned 在活动区（其余照旧 compact），工程态蒸发消失、主观体验追平直推臂，且供给压缩优势保持。**

## 二 · 三臂协议

| 臂 | 上下文方式 | 冻结参数 |
|---|---|---|
| 甲臂（直推） | 每轮完整历史直推 | 同 L15 |
| 乙臂（原版） | CtxKey B＝6，全部条目不 pin | 同 L15（复刻，验证批次一致性） |
| 丙臂（保护） | CtxKey B＝6 ＋ **最新代码条目 pinned**（record 代码 v_n 时解除 v_{n−1} 的 pin） | 其余同 L15 |

- 轮数/焦点表/指令模板/模型/温度/思考关/max_tokens：与 L15 完全一致（`跑-L16三臂.py` 内嵌同表）。
- pinned 是 `ContextItem` 公开字段的**用法层策略**，不改引擎代码、不动打分器——L15「公开缺省不调参」的边界不破。

## 三 · 判据（全部脚本核或逐轮静态核）

| # | 判据 | 核法 |
|---|---|---|
| K1 工程态保持 | 黄铜钥匙在丙臂世界 items 中**逐轮在场**（12/12） | 逐轮静态核（同 L15 取证口径） |
| K2 供给保持 | 丙臂总输入 token ≤ 甲臂 40%，且终轮提示 ≤ 甲臂 25% | 跑账 |
| K3 客观不劣 | 丙臂 O1–O5（L15 同验收器）无一劣于甲臂 | 验收 |
| K4 主观追平 | ΣS(丙) − ΣS(甲) ≥ −1（AI 评，依据公开） | 评分 |
| K5 净效应 | ΣS(丙) − ΣS(乙) ≥ 2 | 评分 |

主观评分沿用 L15 已获园主授权的口径：AI 按「谜题链完整性／文本质量／一致性体感」评 1–5，依据随账公开；园主可随时抽验翻案。

## 四 · 判词映射（预注册）

| 条件 | 判词 |
|---|---|
| K1–K5 全过 | **H16 成立（方向性）**——仍不构成成功率证明 |
| K1 过、K2–K5 任一不过 | **工程态保住了但代价超标**（如实报哪条） |
| K1 不过 | **pin 无效或另有丢失路径**（逐轮取证再挖） |
| 其余中间态 | **部分（只报不判）** |

限度同 L15：n＝1、单题、单模型；任何判词不得写成任务成功率证明。
