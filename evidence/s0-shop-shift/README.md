# S0 · 店铺客服班：三臂同流现场

> ⛔ **数据声明**：本目录内的姓名、手机号、地址与商品码**全部为虚构合成数据**，不含任何真实个人信息
> （号码刻意只差一两位是「串单」陷阱的题面要求；设计约束见 [要求-S0小说班-手写流.md](要求-S0小说班-手写流.md)，
> 完整说明见 [`../../docs/limitations.md`](../../docs/limitations.md) 第 14 条）。

一条 **52 点、8 客户交错**的客服班，三种接法读**同一条流**各跑一遍，客服回复逐字并排：

- **② 单 Agent 直推** —— 一个实例读全史；
- **③ 专家团** —— 三实例各持全量历史，汇总裁决；
- **④ 八爪鱼** —— 分诊／办理／审核三角色，各按页办事，交接留痕。

底座 dsh（DeepSeek Harness），单模型 `deepseek-v4-flash`，2026-08-25 一次跑完（373 发，约 20 分钟）。

## ⛔ 先说这份材料不是什么

- **⛔ 不是生成器 + 种子。**这条班是**手写编造**的（设计约束逐条见
  [`要求-S0小说班-手写流.md`](要求-S0小说班-手写流.md)，那份要求写在造料之前）。
  [`造料-S0.py`](造料-S0.py) 只做格式搬运、标记行拼接与 sha 冻结，**没有随机种子**。
  换种子批量生成是下一版（S1 压力台）的活，不在本目录。
- **⛔ 没有测出长班糊化。**班末单点全输入约 **7.9k token**，三臂 compaction **均 0 次触发**
  （对照：322 条真实客服流上默认压缩一次没触发、请求量涨到 **70,784** token
  —— 那一格的逐 turn 账与口径在 [`../jddc-185-context-growth/`](../jddc-185-context-growth/)，
  ⛔ 其对话内容受 JDDC 许可约束不发布，那儿发布的是数不是料）。
  ⟹ 这个尺寸上 ② 手里全程是全史，四类陷阱对它是开卷考。**②全赢，照报。**
- **⛔ 不是产品化的多 Agent 闭环，也不是「AI 自动运营店铺」。**
  ④ 臂验的是一件窄得多的事：**在一条受控客服班上，分诊／办理／审核三个角色之间的上下文交接结构**
  —— 谁这一步该读哪几页、交接时带走什么、留痕能不能对上。
  ⛔ 它跑在本目录这个一次性实验脚本里，**⛔ 不是本仓引擎的产品接口**；
  ⛔ AgentTeams 适配器、消息总线、分布式 Trace 全部未实现（见 [`../../STATUS.md`](../../STATUS.md)、
  [`../../docs/limitations.md`](../../docs/limitations.md)）。定价、库存、履约、支付一概不碰。
- **⛔ 原始跑数不入本仓**（同本仓既有政策，留私有研究仓）：五份回复账、汇总账、八爪鱼账均未上传。
  ⟹ ⛔ **第三方在本仓上复现不了 2026-08-25 那次运行的 373 发调用与逐字结果。**
  本目录给的是**料、预注册、装置代码与逐字结果**——够任何人拿同一份公开料
  **复做一次结构相同的新运行**（见文末「重跑：能到哪、不能到哪」）。

## 四类陷阱

| 类 | 埋法 | 点位 |
|---|---|---|
| **串单** | 别的客户在中间提到只差一两位的**近似码**（`SKU-C2M85` vs `C2M58`、`A7X13` vs `A7X31`），落单点用描述指代 | 18 / 38 |
| **过期价** | 活动价在班内某点到期，之后仍有人拿旧价来讲 | 23 / 40 |
| **口径漂移** | 同一条口径问题在班的头／中／尾各问一次 | 9·26·47 ／ 20·31·49 |
| **长睡召回** | 早期说的刻字串（`LX-7734`／`LX-5108`），四十多点之后才落单 | 44 / 50 |
| （丢单） | 客户明说下单并给全收货信息，其后 K=3 个同客户点内须出现该 SKU 码 | 6 处 |

## 重跑：能到哪、不能到哪

先把话说死：**⛔ 本目录不是原实验的完整复现包。**

### ✅ 只用本仓、零依赖、当场可核（任何人）

⭐ **下面这四条不用你自己跑也行——[CI](../../.github/workflows/ci.yml) 每次 push 都跑一遍**，
绿灯就在仓库首页。⛔ 它们全部零模型调用，验的是「冻结的还在冻着 / 造料是确定性的 /
装置还跑得起来 / 那道审核闸真的是 fail closed」，**⛔ 不产生任何新读数**。

```bash
sha256sum -c 料-小说班-S0.json.sha256 预测-S0.md.sha256   # 料与预注册没被改过
python3 造料-S0.py                                        # 由料生成跑班料，打印各 sha
```

`造料-S0.py` 是纯确定性的格式搬运（**无随机种子**），任何人跑出的
`设定-S0.txt` / `店规-S0.txt` 应与本目录已提交的两份**逐字节相同**，
`回复料-S0.json` 的 `料sha256` 应是 `915d182c…7ffebc`、统计应是 52 点 / 8 客户 / 14 判定点。

```bash
JDDC239_DRY=1 python3 八爪鱼-S0.py                        # ④ 臂零模型调用走全链（52 点）
cd ../.. && python3 -m unittest tests.test_s0_audit_gate -v  # 审核闸 fail closed 逐种输入验
```

最后那条验的是补丁 A：**解析失败 ／ `"false"` 这种字符串 ／ 缺字段 ／ 空回复，
四种「读不干净」全部倒向退回并标人工复核**——⛔ 不用读代码相信它，跑一下就知道。

### ⚠️ 需要你自己的模型端点（结构相同的**新**运行）

```bash
export FERMION_GARDEN_SRC=$PWD/../../src
set -a; source <你自己的 .env>; set +a
python3 八爪鱼-S0.py
```

这跑出来的是**一次新运行**：同一份料、同一套提示、同一个装置结构，
换成你的端点与你那一次采样。**⛔ 它不会、也不该逐字重现 2026-08-25 那次的回复。**

### ⚠️ 装置代码有过一次跑后补丁

[`八爪鱼-S0.py`](八爪鱼-S0.py) 在 2026-08-26 打了两个补丁（**晚于**那次真跑），
文件头注逐条列明了补丁前的原始代码：

- **补丁 A**：审核结果解析从 fail open 改为 **fail closed**（解析失败或「放行」字段非布尔 ⟹ 退回并标人工复核）。
  ⚠️ 这一处**没有影响那次跑的读数** —— 账上 52 个点是 放行 51 ／ 退回 1 ／ **解析失败 0**，
  fail open 那条分支一次没走过；补丁改的是「下次遇到没遇到过的输入时怎么倒」。
- **补丁 B**：去掉硬编码的本机 `src` 路径，改用 `FERMION_GARDEN_SRC`。纯路径解析，不碰跑法。
